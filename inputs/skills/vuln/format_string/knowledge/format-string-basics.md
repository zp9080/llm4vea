# 适用场景
当程序将用户可控的输入直接作为格式化字符串参数传递给 `printf` 家族函数（如 `printf(buffer)`）时，就会产生格式化字符串漏洞。攻击者可以利用 `%p`, `%s`, `%n` 等特殊说明符，实现信息泄露、任意地址读写，乃至劫持控制流。

本知识适用于以下场景：
- 源码或逆向分析发现 `printf(buf)`、`sprintf(dest, buf)` 等直接使用可控缓冲区的调用。
- 程序交互时，输入 `%p` 或 `%x` 会返回一系列十六进制地址，表明存在格式化字符串漏洞。
- 需要利用漏洞泄露栈上的 Canary、返回地址或 libc 地址，以绕过 ASLR 等保护。
- 计划通过漏洞向内存写入数据，特别是当 `checksec` 显示为 **Partial RELRO** 时，意图通过覆盖 GOT 表项（如 `printf@got`）来实现 RCE。

# 原理要点与利用路径

- **核心原理**: `printf` 等函数根据格式化字符串中的说明符来解析后续参数。如果格式化字符串本身可控，攻击者就可以伪造说明符，让函数错误地将栈上或寄存器中的数据当作参数来解析。

- **关键格式化说明符**:
  - **`%p` 或 `%x` (信息泄露)**: 用于按十六进制打印数据。通过位置参数 `%<offset>$p`，可以精确地打印出栈上或寄存器中任意位置的数据，常用于泄露 Canary、代码基址和 libc 地址。
  - **`%s` (任意地址读)**: 将参数视为一个地址，并打印该地址处的字符串内容。通过将一个想读取的地址（如 GOT 表项地址）放在栈上，再用 `%<offset>$s` 指向它，即可读取任意地址的内容。
  - **`%n` (任意地址写)**: 将**已经输出的字符数量**写入到参数所指向的地址中。这是实现任意写的核心。
    - `%n`: 写入 4 字节 (integer)。
    - `%hn`: 写入 2 字节 (short)。
    - `%hhn`: 写入 1 字节 (char)。这是最常用的，可以实现对内存的逐字节写入。
    - 通过 `%<num>c` 或 `%<num>x` 来填充输出，可以精确控制要写入的数值。

- **利用路径 (GOT 覆写)**: 这是最经典的利用方式，通常分两步。
  1.  **信息泄露**:
      - 利用 `%<offset>$s` 和某个已解析函数的 GOT 地址（如 `puts@got`）来泄露其在 libc 中的真实地址。
      - 根据泄露的地址和符号偏移，计算出 libc 的基地址。
  2.  **任意地址写**:
      - 计算出 `system` 函数的地址和目标 GOT 表项（如 `printf@got`）的地址。
      - 利用 `%n` 家族说明符，分多次、逐字节或双字节地将 `system` 的地址写入到 `printf@got`。`pwntools` 的 `fmtstr_payload` 函数可以自动完成这一复杂过程。
  3.  **触发 Shell**:
      - 发送 `/bin/sh` 字符串。由于 `printf@got` 已被 `system` 地址覆盖，此时调用 `printf("/bin/sh")` 实际上会执行 `system("/bin/sh")`。

- **架构差异 (x64 vs x86)**:
  - **x64**: 前 6 个参数通过寄存器传递。格式化字符串漏洞利用时，位置参数的起始偏移通常较小（如从第 6 个开始），因为可以直接引用栈上的数据。
  - **x86**: 所有参数通过栈传递。位置参数的偏移会更大。

# 调试线索与判定方法

- **GDB/pwndbg 调试**:
  - **确定偏移**:
    - 在 `printf` 调用处下断点。
    - 发送一个唯一标记的 payload，如 `AAAA.%p.%p.%p...`。
    - 检查栈和寄存器，看 `0x41414141` (`AAAA`) 出现在第几个参数的位置，从而确定起始偏移。`gef` 的 `format-string-helper` 或 `pwntools.fmtstr_offset` 可以自动完成此工作。
  - **验证写入**:
    - 对要写入的目标地址（如 `printf@got`）设置观察点 `watch *<addr>`。
    - 当 `%n` 写入时，GDB 会暂停，可以确认写入时机和值是否正确。
  - **检查 GOT 表**: 写入 payload 执行后，使用 `x/gx &printf@got` 检查 GOT 表项是否已被成功修改为 `system` 的地址。
  - **跟踪劫持**: 在 GOT 表被修改后，在下一次 `printf` 调用处下断点，单步进入 (`si`)，观察 `rip` 是否跳转到 `system` 函数。

# 常见陷阱与收敛建议

- **偏移计算错误**: 偏移是格式化字符串利用的生命线。务必精确确定。64 位和 32 位程序的计算方式不同，需要仔细调试。
- **Payload 过长或坏字符**: 使用 `%n` 写入大地址时，可能需要输出大量字符，导致 payload 过长。同时，地址中若包含 `\x00`, `\n` 等坏字符，可能会被输入函数截断。`pwntools` 的 `fmtstr_payload` 会尝试优化 payload 长度并处理坏字符问题。
- **Full RELRO**: 如果 `checksec` 显示为 `Full RELRO`，GOT 表是只读的。GOT 覆写将失败。此时必须寻找其他可写的目标，如 `__free_hook`、`__malloc_hook`（旧版 libc）或栈上的返回地址。
- **一次性漏洞**: 如果漏洞只能触发一次，利用将非常困难。需要在一个 payload 内完成所有操作（泄露、计算、写入），或者想办法将返回地址覆盖为 `main` 或漏洞触发点，以获得多次利用机会。
- **`pwntools.fmtstr_payload`**: 这是生成格式化字符串写入 payload 的最佳工具，它能自动处理分字节写入、填充和偏移计算，强烈推荐使用以避免手动构造的繁琐和易错。
