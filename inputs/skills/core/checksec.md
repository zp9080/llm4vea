# 适用场景
当接触一个全新的 Pwn 题目时，首要任务是使用 `checksec` 工具检查二进制文件的安全保护机制，本知识旨在系统性解读 Canary、NX、PIE、RELRO 等常见保护措施的含义，并基于这些信息初步判断漏洞利用的宏观路径。

# 保护机制
- **Canary (栈保护)**
  - **原理**: 在函数返回地址前插入一个随机的 Cookie 值。函数返回前会检查该值是否被改变，若改变则程序中止。
  - **影响与路径**: 有效防御简单的栈溢出覆盖返回地址。攻击者必须先通过其他漏洞（如格式化字符串、任意读）泄露 Canary 的值，然后在溢出时用原值填回，才能成功覆盖返回地址。

- **NX (Non-eXecutable Stack，不可执行栈)**
  - **原理**: 将数据段（包括栈和堆）标记为不可执行。
  - **影响与路径**: 彻底杜绝了向栈或堆注入 Shellcode 并执行的传统攻击方式。攻击者必须转向**代码重用攻击 (Code Reuse Attack)**，如返回导向编程 (ROP) 或跳转导向编程 (JOP)，利用程序自身或动态链接库中已存在的代码片段 (gadgets) 来构造攻击链。

- **PIE (Position-Independent Executable，地址无关可执行文件)**
  - **原理**: 程序自身的代码段、数据段、BSS 段等在每次加载时都会被随机分配一个基地址。
  - **影响与路径**: 使得代码中的固定地址（如函数地址、gadget 地址）失效。攻击者必须先通过信息泄露漏洞（如利用格式化字符串、部分写或未初始化的变量）泄露程序某个部分的地址，然后计算出程序基址，才能定位到后续利用所需的 gadgets 或函数。

- **RELRO (Relocation Read-Only)**
  - **Partial RELRO (默认)**: `.got` 段部分可写。动态链接器在首次调用函数时会填充其真实地址，此后该条目可被覆盖。这是 GOT 覆写攻击的基础。
  - **Full RELRO**: 在程序加载时解析所有动态链接符号，并将整个 `.got` 段设置为只读。
  - **影响与路径**: `Full RELRO` 能有效防御 GOT 覆写。在这种情况下，攻击者必须寻找其他可写的函数指针进行劫持，例如 `__malloc_hook`、`__free_hook` (在旧版 glibc 中)、虚函数表、或利用 FSOP (File Stream Oriented Programming) 劫持 IO 文件流的虚表。

# 攻击路径
- **攻击路径的决策树**:
  1.  **检查 `checksec`**，建立对保护强度的宏观认知。
  2.  **寻找漏洞类型** (栈溢出、堆漏洞、格式化字符串等)。
  3.  **组合决策**:
      - 若有栈溢出 + **无 Canary** + **无 NX**: 直接 shellcode。
      - 若有栈溢出 + **无 Canary** + **有 NX**: ROP / ret2libc。
      - 若有栈溢出 + **有 Canary** + **有 NX**: 泄露 Canary -> ROP。
      - 若 **有 PIE**: 任何攻击前，必须先泄露程序基址。
      - 若 **Full RELRO**: 放弃 GOT 覆写，转向 hook 或其他可写指针。
      - 若有格式化字符串漏洞，通常是信息泄露的最佳选择，可用来绕过 PIE 和 Canary。
